# D2c Prep: Plan Counts, Hidden Instrumentation, Flakes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before the next paid run (D2c), make these changes:
- a grid count of any whole-number type runs as the int it is, and any other count falls back;
- `online()` refuses a plan it could not record before it spends anything;
- the live-plan fields leave the files the policy-development agent reads;
- the one colour-sensitive test stops depending on `FORCE_COLOR`.

**Architecture:**
- **Counts.** One rule in `see/objective.py:validate_plan` normalises counts for every caller:
  `online()`, replay's scoring, and both live-plan measures.
- **The early check.** `online()` serialises the plan's recordable fields before the baseline
  evaluation and before any agent call.
- **The new file.** `see sweep` writes the live-plan family to a third file, `instrumentation.json`.
  - It goes in a directory given by `--instrumentation`, which the loop points at
    `<workdir>/instrumentation/<round>/`, outside `policy_dev/`.
  - `report_run.py` reads it from there, and the evidence copy includes it.
  - The restart guard names it.

**Tech Stack:** Python 3.10+ standard library (the `see` package), pytest, ruff, pyright. numpy only in tests, where CI's `lasso` extra provides it.

**Spec:** `docs/superpowers/specs/2026-09-26-d2c-prep-design.md`, amended in Task 1 (§3.2 wording), Task 3 (§4.4 evidence pattern) and Task 4
(new §8). Executors read both.

def test_a_whole_number_count_of_any_type_is_the_int_it_is_and_any_other_rejects_the_plan():
    """Listing 2's GridPlan takes integers and the runner checks their range (lines 206-210). A
    numpy integer or an integral float is the plain int it is, so the plan is recorded and frozen
    as ints; a fractional, non-finite or non-numeric count rejects the plan to the fallback grid,
    as an out-of-range count does (GAPS §3, "Grid counts")."""
    import numpy as np  # the lasso extra; an LLM-written policy may well plan with it

    context = GridPlanningContext((), 2, 1, 8, 8, 4)
    whole: list[tuple[Any, Any]] = [(4, 3), (np.int64(4), np.int32(3)), (4.0, np.float64(3.0))]
    for b, r in whole:
        plan = validate_plan(GridPlan(b, r, reason="whole"), context)
        assert plan is not None and plan == GridPlan(4, 3, reason="whole")
        assert (type(plan.branch_count), type(plan.refine_count)) == (int, int)
    other: list[Any] = [4.5, float("nan"), float("inf"), "4", None]
    for count in other:
        assert validate_plan(GridPlan(count, 3, reason="other"), context) is None
        assert validate_plan(GridPlan(4, count, reason="other"), context) is None

def test_a_policy_that_plans_in_numpy_numbers_runs_and_freezes_its_cycle(tmp_path, stub_prompts):
    """A numpy count used to run every attempt of the cycle and then fail to freeze it (int64 is
    not JSON), leaving a half-written trace_pool entry; it is the plain int it is, so the cycle is
    frozen whole on the grid the policy asked for (GAPS §3, "Grid counts")."""

    loop = DreamRSI(
        cfg, make_task(cfg.workdir), ScriptedDiscoveryAgent(seed=7), ScriptedPolicyAgent()
