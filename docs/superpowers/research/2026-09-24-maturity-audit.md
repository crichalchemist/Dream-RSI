# Dream-RSI reconstruction: maturity audit

Scope: `/Users/controlroom/Dream-RSI/reconstruction` (package `see/`, `tests/`, `scripts/`, `tools/`), read-only. Six lens assessments (fidelity, tests, hygiene, runtime safety, seams, docs) were synthesised; every defect/risk claim went through adversarial verification, which corrected severities and refuted two claims (appendix). Paths below are relative to `reconstruction/` unless prefixed.

## 1. Verdict

The mechanical core is faithful, small (about 1,400 lines, stdlib-only) and deterministic: Eq. (1), the M-version argmax with pi_t included, batch legality, success semantics and every GAPS section 3 default match the paper or Listing 2 line for line, the replay-vs-live invariant is pinned by a genuinely strong test, and runs are byte-identical across seeds. The provenance discipline (README, GAPS.md, module docstrings, accurate Listing 2 line citations, self-checking PDF extraction) is the best part of the codebase and should be preserved verbatim. What cannot yet be trusted is the outer loop under real conditions: an interrupted online phase is undetected and a restart silently mixes stale attempts into a "clean" trace; a single malformed evaluator result throws away a whole batch of paid agent runs; nothing ties the deployed policy bytes to the bytes that earned the selecting score; and the paper's 110-call per-round budget is a comment, not a constraint, because the default hard cap admits 992 attempts. The test suite is honestly named but thin where it matters: the selection argmax is verified against a fixture that ties by construction, `validate_plan` and the eq1 objective are untested, and the five tests that cover `loop.py`/`live.py`/`pool.py`/`loader.py` skip silently on a fresh clone, so any naive CI would go green with the loop unexercised. There is no packaging, lint, type check, or CI at all, so the first maturity step is a quality gate that makes the existing 38 tests a real floor rather than a courtesy.

## 3. Confirmed defects and risks (adversarially verified, severity corrected)

### HIGH

**3.1 Interrupted online phase is undetected; restart silently mixes stale attempts; Ctrl-C loses all agent work.** `see/loop.py:124-125`
- Evidence: the guard `if os.path.exists(out): raise RuntimeError(...)` checks `trace_pool/iterNNNN`, created last (`loop.py:155`), while `runs/iterNNNN/tree` is created first (`loop.py:132`, `live.py:143`). `loop.py:142-145` catches `Exception` only, so `KeyboardInterrupt` freezes nothing; `live.py:123` `ThreadPoolExecutor` joins in-flight agents before the interrupt propagates.
- Reproduced with real SIGINT: exit -2, `state.json` iteration 0, `trace_pool/` empty, 16 attempt dirs on disk. Restart with a smaller grid: no exception, manifest `error: null`, 8-cell trace, 8 ghost dirs; every root agent saw 15 stale sibling `proposal.md` files; the next iteration's `history/` link exposed all of them. Following the L125 message literally (remove only `trace_pool/iterNNNN`) leads straight into the same mixing.
- Fix: extend the L124 check to `run_dir` (or write a `.in_progress` marker) with a message naming both dirs; catch `BaseException` around `policy.solve` so a partial tree is frozen with `error` set; `shutdown(cancel_futures=True)` plus process-group kill; README recovery note.

### MEDIUM

**3.2 Replay uses full trace support when `plan_grid` is rejected; live uses the fallback grid; no test pins either.** `see/objective.py:111-113`
- Evidence: `validate_plan` docstring (`objective.py:70`) says "None means use the fallback grid", but `run_episode` passes `branch_count=plan.branch_count if plan else None` and `ReplayQuestion` maps None to the whole trace (`world.py:283-284`). Live does `grid = ... if plan else tuple(self.c.fallback_grid)` (`loop.py:128-129`). `validate_plan` has zero references in `tests/`.
- Reproduced: `GridPlan(999,999)` on a (5,6) trace with fallback (4,5) replayed on 28 probes, `out_of_support=False`, plan recorded None. Direction of bias depends on the candidate's `solve` (in the repro the rejected plan scored lower), but the selection statistic is computed on a different action space than deployment uses.
- Fix: one line in `run_episode` (use `context.fallback_*` when plan is None and `use_plan` is True); parametrised `validate_plan` boundary tests (0, hard_max, hard_max+1, negative); a loop test asserting `used_fallback`/`effective_grid`.

**3.3 Loop tests skip on a dependency they do not semantically use; a fresh clone passes 33/38 and any naive CI goes green with `loop.py`/`live.py`/`pool.py`/`loader.py` unexercised.** `tests/test_loop.py:13-16`

No `pytest.ini`/`pyproject.toml`/workflow enforces the count; `README.md:31` says "38 tests".
- Fix: make the prompt source injectable (`PromptSet` on `LoopConfig`, or a fixture that monkeypatches `see.prompts._read` with placeholder-bearing stubs); keep one loudly named test that needs the real listing; CI runs `tools/extract_listings.py` first and fails on unexpected skips.

**3.4 One malformed evaluator/agent result discards the whole batch; with an exception-swallowing policy the freeze fails after the pool dir exists.** `see/live.py:160-176`
- Evidence: only the agent call (`live.py:150-155`) and `task.evaluate` (`:181-185`) are guarded. `classify_failure(error)` on a non-string raises `TypeError` (`observation_signal.py:47`), `oriented_score` on `'n/a'` raises `ValueError` (`live.py:69`); the exception escapes `list(pool.map(...))` (`:124`) before `self.cells[cell.id] = cell` (`:127`), while `world.py:235` already advanced `_depth`.
- Reproduced: with ParallelRefine the exception is caught at `loop.py:142-145`, manifest `error` set, probes=0, siblings' `score.json` on disk but absent from the trace (contradicts the intent at `live.py:152`). With a policy that swallows `probe_batch` exceptions: `online()` raised `ValueError branch 0 is not a chain from attempt 0` at `loop.py:156`, after `os.makedirs(out)` at `:155`; restart hits the L125 error. Replay cannot catch such a policy because `ReplayQuestion._execute` never raises.
- Fix: per-attempt try around all bookkeeping returning a failed `Cell` (new `fail_class` `runner_error`); validate `combined_score` type; `as_completed` and never drop completed siblings; build the `Trace` before creating the pool dir.

**3.5 Policy-development agent and LLM policy code can rewrite the archives and trace pool that score them; no code/score integrity check.** `see/loop.py:176-185`

The floor at `loop.py:171-174` is swept but discarded, so pool tampering does not move selection (claim overstated there). Latent today (real agents "wired, not run"); high the day a real agent runs.

## 5. Suggested order

1. **A. Quality gate** - nothing else is safe to change until 38 tests are a hard floor on a clean clone and CI runs the extraction step.
2. **B. Test hardening** - every defect in section 3 needs a failing test before its fix; the selection-tie fixture and prompt injection are the cheapest, highest-leverage items.
3. **D. Fidelity and ledger** - small, mostly decisions plus GAPS rows; closes 3.6 and 3.9 and stops the ledger from overclaiming before anyone cites a number.
4. **C. Runtime safety** - the biggest block of code change; do it once tests can pin interruption, malformed results, integrity and atomic writes.
5. **G. Docs and DX** - cheap; land after D so the GAPS split and README reflect the decided semantics, but before external contributors arrive.
6. **E. Platform seams** - the refactor that makes it a platform (agents, tasks, prompts, objectives); only worth doing on top of a green gate, pinned semantics and a loop that survives failure.
7. **F. Reproduction readiness** - the goal state; a Lasso re-measurement on Linux CI and one audited real-agent run, then KernelBench through the new task seam.
